## Repeated review and repairs

1. **Architecture:** replaced fixed ten-piece characters with artwork-backed polygons and a connection graph. Preserved the classic editor for older files.
2. **Workflow tests:** repaired image imports blocking text revisions, selected-piece context, Create appending a second character, unsaved prompt text, immobile fixed-to-pivot changes and reference art leaking into Shadow view.
3. **Artwork correctness:** adopted new images before applying references to them; image edits replace unlocked artwork only when coordinates match. Changed dimensions preserve old clipped artwork and require retracing. Locks also prevent ancestor movement from changing a protected part.
4. **Fabrication audit:** improved scale precision, checked distinct overlapping pin holes, united tab boundaries, blocked incomplete cut contours, paginated long connection guides, and added Chinese print instructions and layer order.
5. **Live prompt audit:** tested the footballer, skirt and six-tentacle cases; added geometry-informed repair after real failures. Advice-only or invalid replies never become a claimed successful design.
6. **Image-to-parametric workflow:** added local extraction, reviewed splitting, dimensions and direction controls. Event tests exercise cleanup, color selection, extraction, split/hinge acceptance, deformation, connection following, export and portable reload without AI POST requests.
7. **Second fabrication review:** fixed contour union tolerances for small image coordinates. Preserved physical scale through added/deleted geometry, including small first pieces. Forced background comparisons to show image pixels even when the main view is Shadow or the reference is hidden. Cleared unfinished click tools when importing an image or selecting another piece.
8. **Live image relay integration:** connected the new editor to Kimi's existing image route without altering the provider service. Added separate generation/editing/vision capabilities, exact prompt plus preset transport, bounded image decoding, and visible image acceptance. Verified real generated PNGs through local geometry conversion and SVG export. The tentacle count failure is recorded as a visual defect, not a successful custom design.
9. **Student interface revision:** established the Create/Refine concept direction, selected-piece dialogue, thumbnails and navigation tools. The v0.5 simplification now uses one next action rather than required construction substeps, result/original review rather than a default three-way comparison, and collapsed optional controls. These are implementation changes, not evidence of classroom usability or verified device rendering.
10. **Fresh-session requirement:** removed automatic project save/restore from both editors. Explicit file downloads and imports remain. Old v2/v1 snapshots are cleaned best-effort, reopening/reloading starts fresh, and the protected AI endpoint preference is kept separately.

11. **Simple cleanup-to-movement flow:** added reviewed largest-component cleanup, keep-more/manual subject selection, two-point Add movement and compact joint-angle testing. Rebuilding existing geometry is disclosed; protected pieces block rebuilding. These local operations do not recognize anatomy or reconstruct hidden image content.
12. **Generation instructions:** preserve the exact student prompt and selected settings. Compact guidance against unrequested text, stars, borders and scenery is optional when the legacy image route has room within its complete 800-character prompt. V2/text inputs retain 4,000 characters; no fresh live output validates the revised guidance.
13. **v0.5.1 prompt-budget hotfix:** corrected a 37-character panda prompt expanding to 1,335 characters and receiving the raw `prompt` error. The adapter checks the complete legacy request before sending; Create uses route-specific limits, an always-visible live character count accounting for selected settings, and in-form progress/errors. Student text and selected presets are never truncated to fit. The live panda attempt timed out before an HTTP response.
14. **v0.6.1 joint simplification:** replaced the default two-point cut with one bend-point tap and a reviewed geometric proposal. Existing-piece joins now select two pieces without manually locating their anchors. Both connected contours retain real overlap material around matching holes, with a visible back/front distinction and explicit layer swap. Movement testing changes a preview copy; accepting keeps the original resting pose. The manual cut and two-anchor tools remain optional.

15. **v0.7.0 automatic joint plan:** added bounded local bend candidates, one AI selection request and a single editable numbered-dot review after cleanup acceptance. Student edits rebuild from the original geometry without more AI calls. Invalid dots require correction/removal; accepting the complete plan is one undoable operation. Automatic magenta and opt-in black mark detection retain source pixels. A live text/outline horse request selected the supplied neck/foreleg candidates; no image understanding is claimed.

## Release judgment

The current workflow prepares movement suggestions automatically, reducing the need to locate every joint from scratch. It retains review of character cleanup, explicit dot editing and one acceptance for the joint plan. Both pieces still receive real overlap material and matching pin holes. Full v0.7.0 automated totals, build/smoke results and browser observations are pending integrated verification; historical counts and screenshots in [VALIDATION.md](VALIDATION.md) apply to their named releases.

The new live AI evidence is one successful text/outline selection request, not visual anatomical analysis. Automatic anatomical separation, hidden artwork reconstruction and dependable prompt matching remain incomplete. Local geometry must validate every selected or manually moved dot; no AI-selected coordinate bypasses those checks. Numeric defaults are paper-prototype heuristics, not universal material norms.

The reference footballer, ornate historical figure and tentacled scholar remain acceptance scenarios. Test the automatic flow in an actual browser, then on phone/tablet and a paper prototype before claiming classroom or physical success. Previous manual-flow checks do not establish the new batch interface's usability.
